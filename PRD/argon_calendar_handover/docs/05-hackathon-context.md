# Hackathon Constraints & Background

## From the participant guide pasted in conversation
- Event: Gemini 4 Argon SF Hackathon, October 25, 2026, SHACK15 (Ferry Building, San Francisco).
- Doors 9:00 AM, kickoff 10:00 AM, hacking 10:30 AM, submission 5:00 PM, first judging 5–7 PM, finals 7–8 PM, winners 8:15 PM.
- Teams: 1–4. New work only; public repositories; 1-minute submission demo video.
- Track 1: Million Token Engineering, track 2: More Dimensions (render/watch/critique/fix 3D loop).
- Judges in first round: live working demo 50%, problem/usefulness 25%, originality 15%, pitch 10%.
- Gemini 4 Argon or Managed Agents should be used meaningfully; real verification loop emphasized.
- Projects to avoid include anything primarily a dashboard. The proposed planner's distinguishing feature should be action-oriented journey reasoning and evidence-backed conflict handling rather than merely calendar/map display.
- Hackathon track fit for this calendar concept is **not guaranteed**; user explicitly prioritizes building a useful idea over winning.

## Why the idea emerged
- User attends many events with locations and wants to know the journey between them and leave-by time.
- Apple's Calendar/Mac displays Time to Leave reminders, suggesting similar user experience can be built using explicit event + routing calculations, rather than tapping a guaranteed public Apple alert API.
- Added a split screen (left collapsible calendar/conflicts sidebar, right map), then online conflict investigation and recognition of optional event tails (e.g. dinner/networking).

## Data security
The original participant guide contained venue Wi-Fi credentials. They are deliberately **not copied into this developer handover**. Do not commit any private API keys or attendee data into a public hackathon repo.
